# S214 网页 ↔ Unity 自动同步 + 一键切关卡

## 第一性原理：最大的摩擦在哪
制作人从"有个点子"到"在游戏里玩到它"要几步？

| | 以前 | 现在 |
|---|---|---|
| 网页画完 → Unity 里玩 | 导出 → 下载 → Unity 关卡库 ▾ → 导入 → 选文件 → 打开 → ▶（**7 步，每次都要**） | 网页点 **▶ 在 Unity 试玩** → 切到 Unity（**2 步**） |
| Unity 里改了 → 回网页看 | 导出 .txt → 网页导入 → 选文件（4 步） | Unity **Ctrl+S** → 切回网页（自动拿到） |
| 换下一关 | 关卡库 ▾ → 打开 → 找名字 | **◀ ▶** 或 **PageUp / PageDown**（两边都一样） |

调研依据：LDtk to Unity "外部编辑器一保存，Unity 就自动重新导入"；Chrome 的文件夹访问（网页经你授权后直接读写项目文件夹，下次一键重连）；GDC 2017《Improving Tool Design Through Editor Triage》：先砍掉迭代回路上的步数。

## 怎么用（只需一次）
1. 用 **Chrome 或 Edge** 打开网页设计台 → 顶栏 **🔗 连接 Unity 项目** → 选 `MarioTrickster` 文件夹（里面有 Assets 的那一层）→ 允许。
2. 之后：网页里一改，停笔 1 秒就写进 Unity 项目；切到 Unity，**自动导入**，打开着的工坊自动换成新版本。
3. Unity 里 **Ctrl+S**（关卡工坊）/ 保存（小镇工坊），切回网页，**自动拿到**。
4. 下次打开网页：点 **🔗 重新连接**（浏览器记得是哪个文件夹）。

Firefox / Safari 不支持连接文件夹：照旧导出关卡包，**拖进 Unity 的 `Assets/Levels/Inbox` 文件夹**，同样自动导入。

## 不会丢东西
| 情况 | 结果 |
|---|---|
| 第一次连接时两边同名关卡不一样 | 以 Unity 项目为准（它在 git 里）；网页那份留一个"（网页旧版）"副本 |
| 连上后两边都改了同一关 | 留网页版本；Unity 覆盖前**自动备份**旧版本（菜单 MarioTrickster → 网页同步 → 打开备份文件夹，每关留 10 份） |
| 网页里画了 Unity 还没实现的新机制，Unity 里又改了这一关再存 | 新机制保留（那一格被你画了别的才去掉） |
| 在网页删掉一关 | 不会被 Unity 那边"复活" |
| Unity 正在 Play | 等你停下再导入 |
| 同步写错 / 被拒 | 网页按钮变成"同步出错"，点它重连；原来的导入/导出按钮都还在 |

## 另外两个小东西
- 关卡工坊顶栏：**◀ 当前关名 ▶**，切走前自动存；Ctrl+S 直接存（不再弹名字框）。
- 小镇工坊右边：**🤖 模拟玩家玩一天**。S213 的机器人玩家来玩你画的小镇，大约 1 秒出结果，比如"⚠ 站着不躲也全赢：门口视野太空"。

## 刻意没做的（避免矫枉过正）
- 没换成 LDtk / Tiled 插件：我们的文字关卡 + 网页已经覆盖，换格式会丢掉现有的检查、模拟和网页对照。
- 没做本地服务器实时推送：要一直开着一个程序，还可能被防火墙拦。文件夹同步已经够快。
- 原来的导入/导出按钮一个没删：离线、换电脑时仍然有用。

## 验证
- 沙盒：网页关卡包（带新机制字符）→ Unity 关卡库文件 → 网页读回，逐字一样；Unity 再存不丢新机制。
- 沙盒：模拟文件夹跑一遍网页同步：第一次连接、只推变了的、Unity 改了拉回、不重复写。
- **要你确认**：真实 Chrome 的授权流程、切到 Unity 时导入是否马上发生。
