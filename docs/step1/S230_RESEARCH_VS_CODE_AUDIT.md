## 0. 结论
1. **调研要求的、沙盒里能做的编码：S230 补完最后一处后已全部做完。** 唯一的缺口是 S229 开始记录的反应时间只写进了文件，体检不读、F8 反馈包也不带，所以"用真人数据校准机器人"这条链路断在最后一步。S230 已接上。
2. **GitHub 还没有这些效果。** 开发分支 `genspark_ai_developer` 停在 S220；S221–S230 一共 **11 个补丁**只在安装包里。**必须运行 apply_S230.bat 并按 Y**，GitHub 才会和调研方案一致。
3. **GitHub 首页默认显示的 `master` 分支停在 2026-05-19**，比开发分支落后 81 个提交。打开仓库首页看到的是很旧的版本，这不代表补丁没装上。要不要合并到 master，需要你决定（我不擅自改你的默认分支）。
4. 剩下没做的都属于以下三类之一：要你玩才能判断、要美术或音效素材、或者被设计规则"冻结横向扩展"挡住。原因见第 3 节。

## 2. S230 做了什么
- `Step1ExitReport.ParseTown / TownMarkdown`：读 `PlaytestLogs/town_days*.csv`，在体检里加一段"小镇"：
  - 你赢、输、平的天数，带 Wilson 区间。
  - 心掉光结束的天里，有几天是天灾替你打死他的。超过 1/5 就提醒：调长预警或缩小雷区。
  - 你被打死的天数。超过 1/3 就提醒：先看死因。
  - **你的反应时间中位数和机器人的 0.15–0.6 秒对比**：
    - 不到 12 次：先不下结论。
    - 比机器人还慢：说明机器人太灵，sim 的"会躲 60/60"对你偏乐观，提示调哪个参数后重跑门槛。
    - 落在范围里：说明一致。
- F8 反馈包会带上 `town_days*.csv`。
- sim 门槛 S230 检查这几项：
  - 表头一致；游戏真写出的一行能读回来。
  - 反应快、反应慢、天灾白赢、样本太少、去重，这几种情况都判对。
  - 体检里写的机器人范围和 `OverworldBots` 的真实代码一致。
  - 体检和打包都带上了这个文件。
- 反向测试：把打包这行删掉，检查立刻报红。EditMode 测试 +1。
- 不改任何玩法数值。
