# S248：可自定义的世界乐园——分阶段升级

## 最终目标不是一章，而是一种创作空间

用户希望建立《弥留之国的爱丽丝》漫画式的世界观乐园，像目前关卡工坊一样自行创作，并能容纳不同会场、规则、身份、线索、反转和结局。现有小镇与捣蛋者守宝只是这个世界的一种内容，不应成为所有新玩法都必须服从的题材模板。

本轮不把《幕间镇》定为唯一故事，不把每扇门强制变成一张牌，也不迁移Unity引擎。原作的牌组、签证、玩家/发牌者/国民关系可以在以后作为可选世界规则；作者也应该能修改或关闭它们。关于原漫画与剧版的研究，见本任务此前的《从漫画反转到项目升级：小镇即会场方案》。本轮示例使用原创文案，不替最终世界真相定稿；若以后公开发布原作品牌或改编内容，需另行确认相应授权。

## 从第一性原理决定怎么拆

创作空间的广度，不等于地图面积，也不等于机关数量。作者需要决定：谁能行动、追求什么、能观察什么、哪些代价可发生、何时发现新信息、结果如何影响下一个选择。这些决定需要有数据承载，但数据里写出一个新动作不意味着游戏已经能执行它。

因此分为四层：**世界**定义共同背景和会场连接；**会场**定义这场游戏的公开规则与角色；**阶段**组织房间、剧情、揭示和结果分支；**房间**继续交给现有地图/机关/AI工坊。花色、难度和场地名称是可自定义标签，不作为当前能力的强制分类。

另有一个重要区分：**事实、角色陈述与作者解释不混在一起**。先在某阶段显示可观察线索，后在相应揭示阶段解释它。反转可以改写玩家对身份与空间的理解，但不偷偷重判已经结束的守房输赢，也不把作者真相提供给AI当作感知信息。

这一层次是为了减少创作摩擦，不是建立万能脚本引擎。新玩法先能写成草稿，再围绕你实际选定的一个内容实现适配器，避免提前造一堆不用的系统。

## 阶段路线

| 阶段 | 可以交付的创作能力 | 不能提前声称的能力 |
|---|---|---|
| P0 升级前备份 | 旧版本实际文件与Git历史的可恢复快照 | 不把历史测试数字当成本次回归 |
| P1 本轮：世界包与首类运行器 | 编辑世界、会场、阶段分支、线索和揭示；导入导出；流程彩排；可选的守宝房＋剧情运行接口 | 不宣称任意新目标、任意角色或列车玩法已经实现 |
| P2 小镇成为会场 | 房间开场后进入小镇、门间阶段与必达线索、章节结果、世界进度独立保存 | 不用普通闲话冷却代替主线；不先扩到巨大开放城市 |
| P3 按内容扩玩法 | 为选定会场增加一个新目标/角色组合；复用观察、机关、路线和反制 | 不把单一寻宝AI当作完整多人社会模拟 |
| P4 选择世界规则 | 可选牌组、签证、参与者身份、奖励、失败和不同会场解锁；作者可改/关闭 | 不照抄制度后留下奖励矛盾；不锁定唯一终极宇宙解释 |
| P5 创作乐园完善 | 低摩擦图形编辑、依赖完整的内容包、版本兼容、发布前外部试玩 | 不以流程测试代替人类体验判断；不自动公开发布 |

P1 是之后真实关卡需求的容器，而不是世界已经完成。下一阶段最有价值的内容是：用现有72×40以内的小镇验证“房间与街道共同属于一场游戏”，再决定下一个会场是列车、旅馆还是完全原创空间。

## 本轮创作方式

### 网页入口

打开 `Tools/LevelStudioWeb/index.html`，选择顶部的**世界乐园**。不需要Unity许可证即可编辑和流程彩排，旧“画关卡”“大地图”的数据不受影响。

左侧编辑世界背景、入口会场；可以添加或复制会场。中间设置会场的空间、角色、公开条款，点击阶段卡片，在右侧改变文字、关联房间和胜负分支。线索分别写观察事实与作者真相，并选首次观察和重新解释的阶段。会场之间的入口用链接表达。

点击**从世界入口彩排**，便能按玩家视角查看当时可知的内容。到守宝阶段，作者手动选择“守住/失守”以检查分支。这个动作只是注入结果，不是AI实际试玩；没到揭示节点前，作者真相不会显示。改动草稿会清空旧彩排，避免用旧状态错误解释新内容。

世界草稿保存在独立浏览器存储中。**导出 `.worldpark.json` 才是可迁移文件**；同浏览器存储不能代替备份。载入示例或导入新包前，应导出当前草稿。旧网页同步收件箱暂不支持世界包，因此使用世界页自己的导入导出按钮。

### Unity入口

Unity开始页提供**世界乐园**按钮；菜单放在已有的“检查与记录”子菜单中，不新增一批并列工具。世界窗口用于编辑、导入、显式导出保存、结构检查与彩排；可选运行器把现有守宝房与剧情阶段连接。真正生成场景只发生在点击运行时，隔离在 `Assets/Scenes/WorldPark`，不改旧小镇和旧房间生成规则。

当前第一类真实房间运行仍然是**你控制捣蛋者，AI寻宝人拿宝撤离**。不是你先抢宝，也不是突然改成红心问卷。当前运行会话仅内存保存，退出Play后不能声称世界进度已保存；世界独立存档属于P2。

当前本机Unity启动被许可证校验拒绝，无法完成Unity EditMode或PlayMode验收。即使源码通过实际Unity引用编译，也不等于场景运行已经通过。使用Unity入口前请在Unity Hub确认许可证状态，再运行测试中心的EditMode；本轮不擅自修改账号或许可证。

### 新玩法先记下来，不会假装能运行

现在可执行的阶段类型是守宝房、剧情、揭示和结局。`concept` 表示新玩法草稿，例如列车回合、协作任务或其他目标。作者可以保存其空间与规则，未知角色也可以作为待适配草稿保留；涉及它的实际运行会明确拦截。

示例包含一个能用现有房间适配器承载的公告厅会场，以及一个待实现的环线列车概念会场。它们是说明创作结构的样例，不是正式世界观定稿，也不代表列车已经可玩。

## 数据与兼容

`.worldpark.json` v1 保存世界背景、会场、阶段、房间名称、胜负分支、线索和链接。它与旧 `.levelpack.json` 分开，避免旧导入器误读成房间。世界包目前引用现有房间名称，**不内嵌房间网格或美术素材**；分享给另一台电脑时，还需携带相应关卡包与素材依赖。把世界包放进当前项目并不自动创建新机关。空间、花色等文字标签也不自动生成新几何或新规则。

纯逻辑在 `Assets/Scripts/WorldPark/WorldParkPack.cs`，Unity适配器和窗口是独立文件；网页纯逻辑在 `worldpark.js`，表单在 `worldpark-app.js`。示例的唯一来源为 `Assets/Resources/WorldPark/Demo.worldpark.json`，网页构建器从它读取。`index.html` 仍由 `build.py` 生成，不手改成第二份实现。

会场与阶段ID用于引用，改ID后要同步修复分支和链接；内部ID不能含斜杠或控制字符，显示名称不受这一限制。结构预检会指出重复ID、失效引用、缺少入口/结局与线索错误；不会因为一个未来玩法仍是草稿而删除它。流程有有限步数预算，防止作者不小心写出无限循环而卡住彩排。

当前自由度主要在**组织、叙事、分支与内容组合**。真正改变角色动作或胜负规则，需要在P3增加明确的玩法适配器；这是尚未实现的能力，而不是创作工具禁止你提出的新创意。

## 第一阶段运行与公平性边界

关联房间使用原小镇同一套关卡库与样板解析，规范默认名是 `默认恶作剧房间`；早期 `默认房间`、`default` 作为兼容别名。当前运行器先在流程场景出示房间公开信息和已观察提示，玩家点击后才进入原房间准备/开始流程。真正胜负仍由原GameManager产生，结果确认后才转到世界后续阶段。

`Session.roomResults` 独立记录房间胜负事实；`Session.venueResults` 是作者定义的整个会场结果（`results` 是兼容别名）。总体目标可以不同于最后一个房间目标，但必须在公开条款说清楚；剧情结局不会覆盖房间事实。链接可要求 `clear`、`fail` 或 `any`。

当前“发现线索”表示进入相应阶段后出示提示，不是场景实体拾取、真人理解证明或AI实际观察证明。可选线索若有路线绕过发现阶段，检查给出 `clue_discovery_bypass` 警告，未发现的truth不会显示；不强制所有创意都变成必达线索。必达剧情/现场调查事件留给P2。节点正文由作者撰写，结构检查不保证作者没有把谜底提前写进正文，也不证明关卡好玩。

生成只写 `Assets/Scenes/WorldPark` 下的模块场景。已有Build Settings条目与启用状态保持原样；若所需场景已被作者禁用，运行前明确拦截，作者自行决定启用。生成失败会恢复原场景设置、Build Settings及全局时钟。世界独立会话尚未存盘，退出Play后清空；空世界清理不会重置旧模式的时钟。

网页与Unity用同一示例和JSON v1；新类型保留为草稿。网页世界草稿使用独立浏览器键，旧关卡/小镇同步不会读写它。外部语法错误不覆盖当前草稿；结构问题可以明确作为待修复草稿导入，运行仍拦截相关错误。Unity替换未导出修改前提示，内置共享示例不能从窗口导出覆盖。
