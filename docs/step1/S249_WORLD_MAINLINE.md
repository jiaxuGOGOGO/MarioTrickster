# S249：世界乐园成为主体验，二维斜俯视探索成为主视角

**日期：2026-10-19。状态：主流程、实际探索适配器和创作闭环已写入当前Unity项目；原生Unity画面与手感尚未验收。**

本轮依据用户最新授权推进：已有升级前备份，不再把世界乐园保持成旧游戏之外的独立附加模式。旧S248关于“并行可选、保护旧主模式”的产品定位已被替代；仍有价值的地图、素材、碰撞、房间机关和创作内核保留为子工具/片段，不代表继续经营两个主游戏。不创建Git提交，不推送远程。

## 1. 从第一性原理选视角

目标不是“更像漫画截图”，而是让作者构建陌生会场，让玩家在有限但公平的信息下调查、选择、承担结果，然后重新理解先前事实。

| 视角 | 对本项目的收益 | 主要成本/限制 | 当前定位 |
|---|---|---|---|
| 横版为主 | 跳跃、纵深机关、追逐清晰，旧房间能力成熟 | 世界动线被压成左右方向；建筑、街区和多路线调查表达受限 | 降为特定挑战片段 |
| 二维斜俯视/3⁄4像素表现 | 街区、路线、地标、证据点好表达；复用原地图和可换图素材，作者可继续低成本修改 | 建筑遮挡与全图信息容易泄漏；高度表达有限 | 本轮主视角 |
| 完整等轴/旋转3D | 多层建筑和空间戏剧性更强 | 坐标、碰撞、素材、编辑器和运动系统都需重做，暂无玩法收益证据 | 不在本轮迁移 |
| 第一人称/近身第三人称3D | 氛围与局部观察强 | 视野约束更重；现有二维素材、布局工具不兼容；易变成制作成本驱动 | 等有依赖这种空间的会场再验证 |

这里的斜俯视是**二维素材表现＋正交摄像机**，不是把摄像机斜着看二维平面来假装三维。新增近距/远距镜头、边缘夹取、建筑挡人时视觉半透明。镜头变动不改变碰撞、视线判定或已知线索；出口真假不体现在标记颜色上。

参考资料：[摄像机选择应服务探索与核心体验](https://www.gamedeveloper.com/design/key-questions-for-choosing-a-camera-perspective)、[布局设计中的动线、目标与高度表达](https://book.leveldesignbook.com/process/layout)。这是设计/工程权衡，不是已经证实的乐趣提升。

## 2. 已实际改造的主流程

主流程为：**入场 → 公开规则 → 真实会场调查/按需横版挑战 → 提交真实活动结果 → 反转揭示 → 会场结局/下一会场**。

- 顶层菜单收敛为四项：开始页、开始世界、世界工坊、测试与诊断。
- 开始页默认只展示世界主能力；横版与存量工具需主动展开，不再用两个大试玩按钮竞争主体验。
- 世界工坊是会场与流程的主编辑入口。地图空间、横版几何、台词、美术是其子工具；诊断、安全和测试归测试与诊断。
- 默认包替换成32×24的“雾灯小镇”：三个现场调查点、两个不同结果出口，不再默认启动守宝、马里奥日程或“一天结束自动重来”。
- 新增`explore`真实玩法适配器：身体移动、原地图碰撞、近身1.1格且有视线才交互、可选计时、出口条件、结果锁存和确认后提交。
- `interact`线索不再进入阶段自动发现；玩家必须在现场调查。未发现的证据不会在反转时伪装成已经读过。
- 探索事实进入`activityResults`；旧横版真实房间事实仍在`roomResults`。作者的会场结局不覆盖局部失败事实。
- 不强制每个会场守宝，不强制旧小镇M/门/日程数量，不强制倒计时；探索可使用5×4至192×128地图。全失败结局只提醒，不把作者有意设计的悲剧硬判成非法包。

## 3. 创作闭环

在Unity选择`MarioTrickster → 世界工坊 → 会场与流程`。首次读取新版默认样例；如果窗口保留的是之前草稿，可点击“读取示例副本”查看新样例，替换前会保护未导出的草稿。

选择explore阶段后，点击**画当前会场地图**：同一地图画笔工具载入该节点的内嵌地图，旧日程侧栏折叠为几何面板。保存/应用只回写当前世界草稿，不覆盖用户小镇文件；另一个地图窗口的未保存草稿不被替换。线索点、出口坐标与条件在世界工坊表单编辑。改完导出`.worldpark.json`，再点击开始世界。

地图工坊F5/空间预览也进入世界会话，不再默认调用旧日程`BuildAll`。**地图几何预览只测通行与镜头，不构成剧情验收。** 编译后若地图窗口回写绑定失效，会提示重新从世界工坊打开；可先导出地图保存改动，不会默默保存到旧地图。

网页设计台默认进入世界工坊，旧横版首次启动向导不再自动覆盖主页面。可编辑世界、规则、阶段、地图文本、点位、线索触发方式与出口条件，也可从当前小镇作者数据只读复制地图。导出的世界包供Unity导入。网页的手动观察和win/lose按钮是**阶段彩排，不模拟物理游戏**。

运行操作：WASD/方向键移动；E调查或选择；N笔记；C镜头远近；-/=细调镜头；Esc暂停。出口选择有确认，结果只能提交一次。

## 4. 默认小镇是验证机制，不是最终内容

雾灯小镇使用原创“灯线与门身份不是同一事实”的调查题：告示、维修单和旧铭牌构成提前可找到的证据链。玩家可以调查，也可以承担猜测风险；不靠强制收集全部线索解锁唯一正确按钮。四条实走验证覆盖调查/不调查与西/东两出口，结果确实分为clear/fail。

这只是证明“空间探索—证据—选择—反转”能在当前架构里成立，不能据此宣称已经有漫画规模的乐园、完整剧情、NPC社会或所有花色玩法。样例的证据可靠性、谜题难度和情绪体验仍需玩家试玩验证；不是复刻原作谜底。

## 6. 删除了什么，暂时不删什么

删减的是旧主模式入口竞争、默认日程试跑、自动一天循环在主会场的绑定、横版首次向导弹窗、探索地图的旧日程硬检查，以及默认开始页堆叠的存量功能说明。没有为“大胆”盲删仍被房间片段、存量作者文件或回归测试引用的碰撞、地图、换图与机关内核。

旧大机关在新探索适配器里目前只是地形/装饰，其雷云、日程或捣蛋技能**尚未迁移**；工具会说明，不把画出图标当作机制已运行。用户原地图、关卡、自定义台词与MyArtKit不改写。升级前备份保持原状。

## 7. 下一阶段的优先次序

1. **原生Play验收与删残留**：在有效许可证环境体验一次完整会场，检查进场、调查、出口确认、反转、退出和两个镜头；记录首条会场的可读性/推理公平性，不先添加更多宏大系统。
2. **空间创作升级**：让调查点/出口直接在画布摆放，维护地图缩放平移后的坐标；以空间事件连接阶段，而不是手写坐标和切场景承担全部叙事。
3. **身份与人物**：角色控制从trickster/player字符串发展为明确能力配置、NPC有限信息和选择后果；原AI感知原则仍适用，但守宝H1不能推广为所有会场硬规则。
4. **多会场世界**：世界进度存档、入口状态、解锁条件、世界编辑器；不同会场可以采用不同目标。不把签证、花色或排行榜先做成强制全局数值枷锁。
5. **第二种真实玩法**：选一个真正需要时序、合作或资源权衡的会场作为适配器验证；不是再复制同一调查模板。只有高度/镜头限制真的妨碍此玩法时，才为该会场试新的视角。

最终方向：**一个可由作者创作、玩家调查并承担后果的世界乐园；不是“给旧守宝加世界观皮肤”，也不是先做无边界空世界再补玩法。**
