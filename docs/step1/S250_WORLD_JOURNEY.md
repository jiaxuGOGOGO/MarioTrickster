# S250 世界旅程：点位画布 · 自定义结局标签 · 世界检查点（2026-10-19）

## 为什么做这一轮

最终目标是“一个由多个会场组成、可以自定义的世界观乐园”。S249 已经让单个会场成立：玩家真正进入俯视地图，靠近并看见才能获得线索，出口结果来自真实活动。要从“一个会场”变成“一座乐园”，从第一性原理看还缺三样东西，本轮逐一补上：

| 缺口 | 不补会怎样 | S250 的做法 |
| --- | --- | --- |
| 作者放点位只能手写坐标 | 创作摩擦大，点常常落在墙里或走不到的位置，作者会放弃尝试 | Unity 与网页都提供探索点位画布：点放调查点/出口、移动、删除、撤销/重做；只接受从唯一出生点 T 走得到的可通行格 |
| 会场结果只有 clear/fail | 只能做“过关/失败”二分，无法表达“被记录”“拿到通行证”等世界语义，失败也只能是终点 | 结局标签由作者自定义（clear/fail 仍兼容），会场链接按同名标签解锁；`any` 保留为链接通配 |
| 没有跨会场进度 | 每次都从头开始，多会场旅程无法试玩，也无法检查后续会场的解锁 | 世界检查点：在剧情、揭示、结局等安全阶段自动保存，可“继续旅程” |

## 默认示例：三会场旅程

默认示例 `Assets/Resources/WorldPark/Demo.worldpark.json` 现在是一条三会场的原创旅程，用来示范上面三项能力如何组合：

第一会场“雾灯小镇”保持 S249 的调查与双出口。通过（clear）后解锁第二会场“检修回廊”；失败（fail）不会卡死，而是走向第三会场“旅程记录层”，检修回廊保持锁定。

第二会场“检修回廊”是路径与时间题：90 秒内取到检修单再回到南侧验收出口才算通过；北侧观景出口是失败出口；路线牌提供线索。无论通过或超时，都可以前往记录层。

第三会场“旅程记录层”没有计时，两个结局使用自定义标签 `recorded` 与 `unfinished`，用来示范“结果不只是胜负”。前面会场的 fail 记录会保留，不会被后来的结果改写。

## 怎么用

在 Unity 里，开始页现在有“开始世界”“继续旅程”“世界工坊”三个主按钮。世界工坊工具栏也有“继续旅程”；只有当前这一版世界内容已经有检查点时它才可点。暂停菜单可以手动保存检查点，或保存后结束本次旅程。

画点位：在世界工坊选中某个会场的 explore 阶段，下方会出现点位画布。点“+ 调查点”或“+ 出口”后点击地图格子；点墙、越界或走不到的格子不会写入，并在画布下方说明原因。新建调查点时会同时建立一条标为【未写草稿】的 interact 线索，请在线索表单补写提示、真相和揭示阶段。按 Ctrl/Cmd+滚轮缩放，中键拖动平移。

自定义结局标签：在结局阶段的“结局标签”里写任意非空标签（例如 `recorded`、`pass_with_ticket`），再在会场链接里把“需要的结果”写成同名标签。如果某个链接要求的标签在来源会场里永远不会出现，结构检查会给出警告。

网页设计台的“世界工坊”页有同样的点位画布和自定义标签字段，导出 `.worldpark.json` 后可在 Unity 世界工坊导入。

## 检查点的规则（为什么这样设计）

检查点只在剧情、揭示、结局这些安全阶段保存，房间与探索进行中不保存。原因是：如果活动中途可以存读，玩家就能反复读档刷出想要的结果，会场的抉择就失去重量。

检查点按世界内容指纹隔离：存档文件名来自整份世界内容的哈希，改了世界内容后旧进度不会被错误套用到新世界。恢复时不是直接相信存档里的状态，而是把记录下来的动作在同一份世界上重新执行一遍，再与存档状态比对；被改过、超出大小上限（字符数和 UTF-8 字节数都受限）或与世界不符的文件会被拒绝，并且不会覆盖原文件。写入先写临时文件、读回校验，再替换正式文件，上一份保留为 `.previous`。

存档位置在 Unity 的 `Application.persistentDataPath/WorldPark/` 下，不在项目目录里，不会进入 Git，也不会覆盖用户的关卡、地图或台词文件。
